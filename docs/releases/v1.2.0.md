Hayat v1.2.0 adds account security (two-step verification, passkeys, lockout and step-up confirmation), sign-in through Google, GitHub and company SSO, per-service login pages, service enrollment codes, and agents as a principal kind. Operators running Hayat should read the Upgrading section before deploying; developers integrating services should note the new versioning contract.

## Highlights

### Two-step verification, passkeys and account security
Accounts can now use TOTP authenticator apps and passkeys (WebAuthn), with one-time recovery codes. Ten wrong passwords lock an account, new passwords are checked against Have I Been Pwned, and sessions have an idle timeout. A tenant can require two-step verification for all its members with `SetTenantRequireMFA` or the tenant's "Require two-step verification" switch in the console.

### Step-up confirmation for sensitive changes
Sensitive calls (removing a factor, new recovery codes, promoting or disabling a user, rotating keys, deleting or handing over a tenant) now need the caller to have confirmed it's them in the last ten minutes. Otherwise they fail with `PERMISSION_DENIED` and the response header `hayat-step-up: required`; the console sends the person to `<issuer>/reauth` and back.

### Sign in with Google, GitHub and company SSO
The instance can be configured with Google, GitHub and one company OpenID Connect provider, and a tenant can connect its own provider and prove its email domains with a DNS TXT record. A verified domain can offer company sign-in alongside the password or enforce it. People link outside accounts from Account → Sign-in methods.

### Custom login pages per service
Each service's owners design its sign-in page in the console (Services → a service → Login page), with a draft, published versions and history. Hayat's own sign-in pages render the design, so single sign-on and password managers keep working. Designs are data, never markup.

### Service enrollment codes
An owner (or an instance admin, for a service not registered yet) creates a one-time enrollment code and hands it to a deployment, which redeems it once on the api role to receive its credentials. Redeeming for an existing service rotates its API secret, so nobody copies a client secret by hand.

### Agents as a principal kind
An agent is a member kind of its own: no email, password, session or admin role, living in exactly one tenant and answering to a sponsor there. Grants can name an agent like a person, and permissions marked `people_only` are never granted to one. Tenant admins manage their tenant's agents with `hayat.agents.manage`.

### Fixes and polish
- Per-app themes: a person can give one app a theme of its own while the rest follow the account theme (`SetMyAppAppearance`).
- Avatars and logos for people, tenants and services, stored in a directory or S3-compatible bucket set by `HAYAT_STORAGE`.
- Turnstile on sign-up and forgot password.
- Console: dev console, loading animation, updated resource tree view, and a fix to the agent SQL migrations.

## Upgrading

Run `hayat migrate` before starting the new version: migrations 0007 through 0013 add login pages, media, sign-in providers, account security, agents, service enrollments and per-app appearances, for both PostgreSQL and YugabyteDB. Set `HAYAT_STORAGE` if you want uploaded images kept in an S3-compatible bucket; login page logos from 0007 are moved into the store by the admin role at boot. Services that call the new RPCs must declare v1.2.0 as their minimum Hayat.

## Service API

- `AccountService.SetMyAppAppearance` — give one app a theme of its own, or send it back to the account's.
- `AccountService.SetMyAvatar` — set the caller's picture (PNG, JPEG or WebP up to 5 MB), which becomes the OIDC `picture` claim.
- `AccountService.GetMySecurity` — the caller's authenticator apps and passkeys, recovery codes left, whether a tenant requires a second factor, and the setup and reauth URLs.
- `AccountService.RemoveMyFactor` — remove one of the caller's factors; needs a recent confirmation.
- `AccountService.RegenerateRecoveryCodes` — issue a fresh set of recovery codes, voiding the old one; needs a recent confirmation.
- `UserService.ResetUserFactors` — remove every factor for someone who lost them all and sign them out everywhere; needs a recent confirmation.
- `UserService.GetUser` — now returns the user's `factors`.
- `TenantService.SetTenantLogo` — set a tenant's logo (PNG, JPEG or WebP up to 5 MB); empty data removes it.
- `TenantService.SetTenantRequireMFA` — require every member of a tenant to sign in with a second factor; needs a recent confirmation.
- `Tenant` — new fields `logo_url` and `require_mfa`.
- `Appearance` — new fields `accent_text` and `scale`.
- `GetMyAppearanceResponse` — now lists every app the caller can theme in `apps`.
